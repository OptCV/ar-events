# DATA_MODEL.md — Canonical Scene, Assets, Revisions

## Principles

- Typed, versioned JSON canonical scene; never derive core scene meaning from USD or GLB outputs.
- **Tracking targets** and **display images** are different semantic asset roles.
- Every generated asset has a recorded source, transform settings, converter version and validation status.
- Published revisions are immutable; drafts are mutable; public URL points to an atomically promoted ready revision.
- Store position in **meters**, rotation as **quaternion `[x,y,z,w]`**, scale as `[x,y,z]`.

## TypeScript sketch

```ts
type Vec3 = [number, number, number];
type Quat = [number, number, number, number];
type Transform = { position: Vec3; rotation: Quat; scale: Vec3 };
type Placement =
  | { mode: 'image'; trackingTargetAssetId: string; physicalWidthMeters: number }
  | { mode: 'floor'; preferredSurface: 'horizontal' }
  | { mode: 'wall'; preferredSurface: 'vertical' };
type SceneNode =
  | { id: string; kind: 'model'; assetId: string; transform: Transform; parentId?: string }
  | { id: string; kind: 'image-object'; derivativeId: string; transform: Transform; parentId?: string }
  | { id: string; kind: 'text'; text: string; style: Record<string, unknown>; transform: Transform; parentId?: string }
  | { id: string; kind: 'panel'; content: string; transform: Transform; parentId?: string }
  | { id: string; kind: 'primitive'; shape: 'box'|'sphere'|'cylinder'|'plane'; transform: Transform; parentId?: string }
  | { id: string; kind: 'hotspot'; actionId: string; transform: Transform; parentId?: string };
type Action =
  | { id: string; type: 'open-url'; url: string; label?: string }
  | { id: string; type: 'mailto'; address: string }
  | { id: string; type: 'tel'; number: string }
  | { id: string; type: 'play-animation'; nodeId: string; clip: string }
  | { id: string; type: 'toggle-visibility'; nodeId: string };
interface ExperienceRevision {
  schemaVersion: number;
  placement: Placement;
  nodes: SceneNode[];
  actions: Action[];
  primaryActionId?: string;
  appearance: { accentColor: string; logoAssetId?: string };
}
```

This is a *sketch*, not final Zod schema. Ensure every node has optional style, visibility and capabilities as needed; write exhaustive schema validation and typed migrations.

## Relational models

| Table | Key fields |
|---|---|
| `user` (+ `session`, `account`, `verification`, `rate_limit`) | Owned and generated by Better Auth (ADR-013); `user.id` is text. App tables reference `user.id`; no separate `users` table |
| `experiences` | id, owner_id, slug, draft_revision_id, published_revision_id, visibility, timestamps |
| `experience_revisions` | id, experience_id, schema_version, config_json, validation_report, created_at |
| `assets` | id, owner_id, purpose, mime, size, checksum, r2_key, metadata, state |
| `asset_derivatives` | id, source_asset_id, output_type, settings_json, converter_version, r2_key, checksum, status |
| `processing_jobs` | id, type, idempotency_key, revision_id/asset_id, attempt, state, diagnostics, timestamps |
| `generated_outputs` | id, revision_id, runtime, r2_key, validation_json, state |
| `analytics` | id, public_experience_id, event_type, anonymous aggregate fields, timestamp |

Use foreign keys, owner checks, unique slugs and constrained state enums. Store image object and target references separately; do not infer role from MIME type.

## R2 keys

```
users/{userId}/assets/{assetId}/original
users/{userId}/assets/{assetId}/derivatives/{hash}/display.glb
users/{userId}/assets/{assetId}/derivatives/{hash}/display.usdz
experiences/{expId}/revisions/{revId}/scene.json
experiences/{expId}/revisions/{revId}/ios/experience.usdz
experiences/{expId}/revisions/{revId}/android/experience.glb
```

Use immutable revision keys for published outputs and signed access for drafts. Standardize MIME types: GLB `model/gltf-binary`, USDZ `model/vnd.usdz+zip`.

## API surface

`POST /api/experiences`, `PUT /api/experiences/:id/draft`, `POST /api/assets/uploads`, `POST /api/assets/:id/convert-image-to-ar`, `GET /api/assets/:id/derivatives`, `POST /api/experiences/:id/validate`, `POST /api/experiences/:id/publish`, `GET /api/experiences/:id/jobs`, `GET /api/public/experiences/:slug`.

All private routes require ownership checks; public ones resolve published revision only.

## Implementation status (2026-11-14)

Implemented in `packages/db` (ADR-017): Better Auth `user`/`session`/`account`/`verification`/`rate_limit`, plus `experiences`, `experience_revisions`, `assets`, `asset_derivatives`, `processing_jobs`, `generated_outputs`. The schema source is `packages/db/src/schema/`; migrations are in `packages/db/migrations/`. Revision states: `draft` (only mutable state), `snapshot`, `compiling`, `partially_ready`, `published`, `failed`, `superseded`. `analytics` is not implemented yet.

### Milestone 4 additions (2026-11-15)

- `experiences.draft_version` (migration `0002_draft_version`): optimistic-concurrency counter for draft saves (ADR-021).
- Draft scenes are stored as `DraftExperienceScene` (image placement may have `trackingTargetAssetId: null`); publishing will require the strict `ExperienceScene`.
- Implemented API: `GET/POST /api/experiences`, `GET/PATCH/DELETE /api/experiences/:id`, `PUT /api/experiences/:id/draft`, `POST /api/experiences/:id/validate`. Contracts are in `packages/contracts/src/experiences.ts`.

### Milestone 5 additions (2026-11-22)

- `assets.upload_expires_at`, `assets.upload_claimed_at`, `assets.rejection_code` (migration `0003_asset_uploads`), with CHECKs: `pending_upload` needs an expiry; `rejected` needs a code (ADR-022).
- Asset lifecycle used today: `pending_upload` → `validated` (checked while streaming) or `rejected`; `deleted` is a transient state during deletion. `uploaded` is reserved for future asynchronous validation.
- `assets.metadata`: `{ image: { width, height, mayHaveAlpha } }` or `{ model: { gltfVersion, generator?, meshes, materials, textures, animations, extensionsRequired } }`, plus `warnings[]`; `declaredSha256` while pending.
- Implemented API: `POST /api/assets/uploads`, `PUT /api/assets/:id/content`, `GET /api/assets`, `GET/DELETE /api/assets/:id`, `GET /api/assets/:id/content` (signed). Contracts are in `packages/contracts/src/assets.ts`.
- R2 bindings: `ASSETS_BUCKET` → `ar-creator-assets` / `ar-creator-assets-dev`; only originals are stored so far.

### Phase 2 Milestone 1 additions (2026-11-22)

- Migration `0004_image_to_ar_jobs` (ADR-023): `processing_jobs.input` (immutable job input: `{kind: "image-object", settings, settingsHash, glbConverterVersion, usdConverterVersion}`), `processing_jobs.error_code` (required when `failed`; values = contracts `CONVERSION_ERRORS`), index `(owner_id, asset_id, created_at)`; `asset_derivatives.size_bytes` (required when `ready`), SHA-256 format and `users/%` key prefix checks.
- Image-to-AR jobs: `type = convert_image_to_ar`, `idempotency_key = i2a:{assetId}:{settingsHash}:{glbVersion}+{usdVersion}`, `attempt` 1..3 (restart after failure increments it). Derivatives: `image_object_glb` (`image-to-ar@0.1.0`) and `image_object_usdz` (`usd-image-plane@0.1.0`), unique per provenance, R2 key `users/{uid}/assets/{assetId}/derivatives/{sha256(settingsHash + "
" + converterVersion)}/display.{glb|usdz}`.
- Implemented API: `POST/GET /api/assets/:id/image-objects`, `GET /api/conversions/:id`, `GET /api/derivatives/:id/content` (signed). Contracts are in `packages/contracts/src/conversions.ts`.
- Storage usage = originals + ready derivatives.
- Milestone 8 (ADR-025): migration `0005_texture_derivatives` adds `derivative_type` value `image_object_texture` (prepared PNG/JPEG texture, settings `{maxEdge: 2048}`, converter `texture@0.1.0`, key `…/derivatives/{hash}/texture.{png|jpg}`); internal only (never served). GLB/USDZ converter versions now include the texture policy (`image-to-ar@0.1.0+texture@0.1.0/max2048`, `usd-image-plane@0.1.0+texture@0.1.0/max2048`). `assets.mime_type` may be `image/webp` for display images.
- Milestone 7 (ADR-024): scene `image-object` nodes store the **GLB** derivative id; the USDZ partner is found by source + settings hash. `GET /api/image-objects` lists complete pairs.
